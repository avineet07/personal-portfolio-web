# Webpage Generation Standards & Design System Architecture

A comprehensive specification and architectural guideline for generating, structuring, and maintaining a high-impact, professional data science and engineering portfolio.

---

## 1. Portfolio Philosophy & Information Architecture

A senior engineering and data science portfolio is evaluated in two distinct phases:
1. **The 30-Second Recruiter / Executive Scan**: Clear identity, immediate proof of seniority, domain pillars, high-level impact metrics, and seamless resume access.
2. **The 10-Minute Technical Committee Deep Dive**: Systems architecture diagrams, algorithmic trade-offs, production benchmarks, data pipelines, and code artifacts.

### 1.1 Structural Hierarchy & View Routing
The site uses a clean SSR/SSG tri-page architecture connected via semantic URL parameters:
- **Executive Summary (`/?page=home`)**: The primary landing view. Highlights name, headline, bio summary, 4 Core Architectural Pillars, recent featured work, and interactive skills matrix.
- **Production Work (`/?page=work`)**: Deep enterprise case studies (e.g. Sears Holdings, OneCard, Auronova Consulting) focused on scale, ROI, cost savings, and architectural migration.
- **Deep-Dive Projects (`/?page=projects`)**: Autonomous technical explorations (e.g. LangGraph agents, CDC streaming pipelines, Data Mesh, predictive LightGBM).
- **Interactive Detail Reader (`/?post=<slug>`)**: Client-side modal overlay with full-screen expansion, deep linking, and pushState history tracking.

## 2. HTML5 Semantic & Accessibility Standards (WCAG 2.1 AA)

Every page generated by this pipeline adheres to strict semantic and accessibility rules:

### 2.1 Landmark Elements
- `<header role="banner">`: Houses primary branding, navigation links, and theme toggle.
- `<main id="main-content">`: Wraps primary page content; targets skip-to-content links.
- `<aside aria-label="Filters">`: Encloses filter sidebars and sorting dropdowns.
- `<section>` & `<article>`: Used exclusively for discrete content blocks and case study cards.
- `<dialog>` / `<div role="dialog" aria-modal="true">`: Used for the detail reader modal with `aria-labelledby` referencing the article title.

### 2.2 Accessible Form & Filter Controls
- All dropdowns (`<select>`) must have an explicit `aria-label` or `<label for="...">`.
- Checkbox filter controls must use `<label class="filter-checkbox">` with the `<input type="checkbox">` properly nested.
- Filter buttons must specify `type="button"` and communicate state changes dynamically.

### 2.3 Keyboard & Focus Trapping
- The Detail Reader traps focus within the modal when open.
- Pressing `Escape` closes the reader and restores focus to the triggering card button.
- All interactive cards support keyboard activation (`Enter` / `Space`).

### 3.2 Fluid Typography via `clamp()`
Headlines and hero titles must scale smoothly without abrupt media query jumps:
```css
.home-hero-title {
  font-size: clamp(2.2rem, 5vw, 3.8rem);
  font-weight: 800;
  letter-spacing: -0.03em;
  line-height: 1.15;
}

.home-hero-headline {
  font-size: clamp(1.05rem, 2vw, 1.35rem);
  color: var(--accent-blue);
}
```

### 3.3 Cards & Content Grid Architecture
- **CSS Grid with `auto-fit`**: Used for metrics and architectural pillar layouts:
  `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));`
- **Subgrid & Equal Heights**: Card action buttons anchor to the bottom using `margin-top: auto` on card flex containers.
- **Glassmorphism**: Backdrop blur with subtle translucent borders creates dimensional layering:
  `backdrop-filter: blur(12px); border: 1px solid var(--border-subtle);`

## 4. Templating & Component Architecture (Jinja2)

All visual elements are decoupled from hardcoded Python dictionaries and rendered via reusable macros.

### 4.1 Unified Content Card Macro (`templates/components/content_card.html`)
The unified card macro handles both Production Work case studies and Project articles:
- Category / Tag Pill badge
- Title and Organization / Topic metadata
- Reading time indicator
- Impact Metrics highlights
- Related Cross-linking chips
- Read / Deep Dive action button with accessible `data-id`

```jinja2
{% macro render_content_card(item, index=0) %}
<article class="content-card work-card" data-id="{{ item.id }}">
  <div class="card-header">
    <span class="card-category-badge">{{ item.category or item.topic }}</span>
    <span class="card-meta">{{ item.period or item.date }}</span>
  </div>
  <h3 class="card-title">{{ item.title }}</h3>
  <p class="card-summary">{{ item.summary }}</p>
  
  {% if item.metrics %}
  <div class="card-metrics-row">
    {% for m in item.metrics[:2] %}
    <span class="metric-pill">{{ m }}</span>
    {% endfor %}
  </div>
  {% endif %}

  <div class="card-footer">
    <button class="btn-card-action work-card-open" data-id="{{ item.id }}" aria-label="Open {{ item.title }}">
      Read Deep Dive &rarr;
    </button>
  </div>
</article>
{% endmacro %}
```

### 5.1 JSON Data Contract (`portfolio_data.json`)
The pipeline compiles into a single structured JSON schema:
- **`profile`**:
  - `name`: Candidate's full name.
  - `headline`: Professional domain title.
  - `introduction`: Executive bio summary.
  - `linkedin`, `github`, `email`, `location`.
  - `skills`: Categorized dictionary (`languages`, `mlAi`, `dataEngineering`, `analyticsAndBusiness`).
- **`resume`**:
  - `pillars`: Array of 4 architectural pillars (`tag`, `title`, `description` list).
  - `workExperience`: Array of roles (`role`, `company`, `location`, `period`, `category`, `summary`, `bullets`).
  - `education`: Array of degrees (`degree`, `institution`, `period`, `field`).
  - `internships`: Array of formative internships (`role`, `company`, `location`, `period`, `description`).
- **`content_meta`**: Cross-referenced articles in `content/work` and `content/projects`.

### 5.2 Grounding & Anti-Hallucination Protocol
All generation is strictly governed by [`src/pipeline/PARSING_GROUNDING_RULES.md`](file:///Users/ashish/Documents/playground/personal-website-portfolio/src/pipeline/PARSING_GROUNDING_RULES.md):
- Zero fabrication of job titles, employers, dates, metrics, degrees, or URLs.
- If a section cannot be grounded directly in `ref/resume/` or `ref/cover_letter/`, it is omitted. Better to not publish than publish unverified claims.

## 6. Performance & Asset Delivery Standards

1. **Vector First (`src/assets/*.svg`)**: Architecture flows and data pipeline diagrams are stored as clean SVGs. They scale crisply to Retina/4K displays, carry zero compression artifacts, and weigh < 20KB each.
2. **Zero Client Frameworks**: Vanilla JS with event delegation for instant modal opens and filter updates.
3. **Static Pre-Rendering (SSG)**: `python scripts/build.py` renders every page into static HTML in `dist/` for edge deployment to Cloudflare Pages (instant sub-50ms TTFB).
4. **Security Headers**: Standard production HTTP response headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`).
